# Terms

The most important terms of this help in alphabetical order.

| Term | Meaning |
|---|---|
| Arrival and departure time | times with booking by day that guests see in the request form and in the mails |
| Blocked period | booking with a blocking status, for example for holidays or maintenance |
| Blocking | a status occupies the period, other bookings cannot overlap it |
| Booking | a period for an object, with a status |
| Booking mode | by day or by period, applies to the whole section |
| Buffer | time that stays free between two bookings |
| Calendar window | the months visitors can reach |
| Changeover day | day on which one booking ends and the next one starts |
| Default view | the view visitors see first |
| Display | several objects or a single object |
| Droplet | placeholder in WBCE, here for the [calendar](droplet.md) anywhere |
| Grid | steps on which start and end of a request lie |
| Lead time | minimum time between the request and the start |
| Maximum advance | how far in the future a request may lie at most |
| Object | what is booked: a flat, a room, a device |
| Object type | group of objects with common defaults |
| Request | booking wish via the form on the website. It is stored as a [booking](requests.md). |
| Role | fixed task of a status in the request workflow |
| Section | a Reservations calendar on a WBCE page, with its own objects, statuses and [settings](settings.md) |
| Status | state of a booking; decides whether it blocks and what visitors see |
